# API Init - API 接口初始化生成

分析當前項目，列出需要提供的 API 接口功能清單，確認後生成對應的接口代碼。

## 執行步驟

1. **分析項目結構與功能**
   - 掃描項目目錄結構，識別主要模組與功能
   - 讀取現有代碼，理解業務邏輯與數據模型
   - 識別需要對外提供的功能點

2. **生成 API 接口清單**
   - 根據分析結果，列出建議的 API 接口清單
   - 每個接口包含：路徑、HTTP 方法、功能描述、請求參數、回應格式
   - 以表格形式呈現給用戶確認

3. **等待用戶確認**
   - 用戶可對清單進行增刪改
   - 確認無誤後才進入生成階段

4. **生成 API 接口代碼**
   - 根據確認後的清單，生成對應的接口實現代碼
   - 遵循項目現有的框架與代碼風格
   - 包含基本的輸入驗證與錯誤處理

5. **生成 `/api/support` 端點**
   - 生成 `localhost:port/api/support` 端點
   - 該端點返回所有可用 API 的元數據（路徑、方法、參數、描述）
   - 格式為 JSON，便於 Claude Code 分析後自動接入對應功能
   - 回應格式範例：
     ```json
     {
       "version": "1.0.0",
       "base_url": "/api",
       "endpoints": [
         {
           "path": "/api/example",
           "method": "GET",
           "description": "功能描述",
           "parameters": [],
           "response": {}
         }
       ]
     }
     ```

6. **更新 API 文檔**
   - 自動執行 api-docs 的邏輯，將接口文檔寫入 `.claude/docs/api.readme`
   - 確保文檔與生成的代碼一致

7. **總結**
   - 列出已生成的接口數量
   - 提示 `/api/support` 端點的訪問地址
   - 確認文檔已同步更新
