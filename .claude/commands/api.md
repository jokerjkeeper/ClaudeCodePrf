# API 統一管理工具

根據子命令執行不同的 API 管理操作。使用方式：`/api {子命令}`

## 支持的子命令

| 子命令 | 說明 |
|--------|------|
| `init` | 初始化生成 API 接口 |
| `ana` | 分析現有接口與項目功能差異 |
| `docs` | 生成 API 接口文檔 |
| （無參數） | 顯示使用說明 |

---

## 參數解析

收到的參數為：`$ARGUMENTS`

- 若參數為空或不在支持列表中，顯示上方子命令表格並提示用戶選擇
- 若參數匹配子命令，執行對應流程

---

## init — API 接口初始化生成

分析當前項目，列出需要提供的 API 接口功能清單，確認後生成對應的接口代碼。

### 執行步驟

1. **分析項目結構與功能**
   - 掃描項目目錄結構，識別主要模組與功能
   - 讀取現有代碼，理解業務邏輯與數據模型
   - 識別需要對外提供的功能點

2. **生成 API 接口清單**
   - 根據分析結果，列出建議的 API 接口清單
   - 每個接口包含：路徑、HTTP 方法、功能描述、請求參數、回應格式
   - 以表格形式呈現給用戶確認

3. **等待用戶確認**
   - 用戶可對清單進行增刪改
   - 確認無誤後才進入生成階段

4. **生成 API 接口代碼**
   - 根據確認後的清單，生成對應的接口實現代碼
   - 遵循項目現有的框架與代碼風格
   - 包含基本的輸入驗證與錯誤處理

5. **生成 `/api/support` 端點**
   - 生成 `localhost:port/api/support` 端點
   - 該端點返回所有可用 API 的元數據（路徑、方法、參數、描述）
   - 格式為 JSON，便於 Claude Code 分析後自動接入對應功能
   - 回應格式範例：
     ```json
     {
       "version": "1.0.0",
       "base_url": "/api",
       "endpoints": [
         {
           "path": "/api/example",
           "method": "GET",
           "description": "功能描述",
           "parameters": [],
           "response": {}
         }
       ]
     }
     ```

6. **更新 API 文檔**
   - 自動執行 docs 流程，將接口文檔寫入 `.claude/docs/api.md`
   - 確保文檔與生成的代碼一致

7. **總結**
   - 列出已生成的接口數量
   - 提示 `/api/support` 端點的訪問地址
   - 確認文檔已同步更新

## ana — API 接口分析與同步

分析當前項目功能與已開發的 API 接口，檢查是否需要新增、更新或刪除接口。

### 執行步驟

1. **分析項目當前功能**
   - 掃描項目代碼，識別所有業務功能模組
   - 理解數據模型與業務邏輯的變更

2. **分析已有 API 接口**
   - 讀取現有的 API 路由與控制器代碼
   - 讀取 `/api/support` 端點的元數據（如已存在）
   - 讀取 `.claude/docs/api.md`（如已存在）

3. **比對差異，生成分析報告**

   ### 需要新增的接口
   | 接口路徑 | 方法 | 原因 |
   |----------|------|------|

   ### 需要更新的接口
   | 接口路徑 | 方法 | 變更內容 | 原因 |
   |----------|------|----------|------|

   ### 建議刪除的接口
   | 接口路徑 | 方法 | 原因 |
   |----------|------|------|

   ### 無需變更的接口
   | 接口路徑 | 方法 | 狀態 |
   |----------|------|------|

4. **等待用戶確認**
   - 用戶可對分析結果進行調整
   - 確認無誤後才執行變更

5. **執行變更**
   - 根據確認後的方案，執行新增 / 更新 / 刪除操作
   - 同步更新 `/api/support` 端點的元數據

6. **更新 API 文檔**
   - 自動將變更同步到 `.claude/docs/api.md`
   - 確保文檔與當前接口狀態一致

7. **總結**
   - 列出本次變更統計（新增 / 更新 / 刪除數量）
   - 確認文檔已同步更新

---

## docs — API 接口文檔生成

分析當前項目的所有 API 接口，生成完整的接口文檔到 `.claude/docs/api.md`。

### 執行步驟

1. **掃描所有 API 接口**
   - 讀取項目中的路由定義與控制器代碼
   - 讀取 `/api/support` 端點的元數據（如已存在）
   - 識別所有已實現的 API 端點

2. **提取接口資訊**
   - 對每個接口提取：
     - 路徑（Path）
     - HTTP 方法（GET / POST / PUT / DELETE 等）
     - 功能描述
     - 請求參數（Query / Body / Path params）
     - 請求範例
     - 回應格式與範例
     - 錯誤碼說明
     - 認證需求（如有）

3. **生成文檔**
   - 將文檔寫入 `.claude/docs/api.md`
   - 使用以下格式：

   ```markdown
   # API 接口文檔
   ## 版本: x.x.x
   ## 最後更新: YYYY-MM-DD
   ## Base URL: http://localhost:port/api

   ---

   ## 目錄
   - [模組名稱](#模組名稱)

   ---

   ## 模組名稱

   ### 接口名稱
   - **路徑**: `/api/xxx`
   - **方法**: `GET`
   - **描述**: 功能描述
   - **認證**: 是否需要

   #### 請求參數
   | 參數名 | 類型 | 必填 | 說明 |
   |--------|------|------|------|

   #### 請求範例
   \`\`\`json
   {}
   \`\`\`

   #### 回應範例
   \`\`\`json
   {}
   \`\`\`

   #### 錯誤碼
   | 狀態碼 | 說明 |
   |--------|------|
   ```

4. **確認輸出**
   - 確保 `.claude/docs/` 目錄存在，不存在則創建
   - 寫入文檔後告知用戶文檔路徑與接口總數
